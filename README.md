# fairness-web

The web app for the on-call fairness tracker: Angular 22 (standalone, zoneless, signals, Signal Forms) with
Angular Material. It talks only to the gateway (`Fairness-Checker`), on the same origin: the dev server
proxies `/api` to it, and in production Nginx does.

## Run it

Needs Node 22.22+ or 24.15+ and a gateway on `http://localhost:8080` (see `Fairness-Checker/README.md`).

```bash
npm install
npm start            # http://localhost:4200, /api proxied to :8080 (proxy.conf.json)
```

| Script                            | What it does                                                                                                                                                                      |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `npm start`                       | Dev server with the proxy                                                                                                                                                         |
| `npm test`                        | Unit tests (Vitest, jsdom)                                                                                                                                                        |
| `npm run lint`                    | ESLint (angular-eslint), templates included                                                                                                                                       |
| `npm run format` / `format:check` | Prettier                                                                                                                                                                          |
| `npm run build`                   | Production build into `dist/`                                                                                                                                                     |
| `npm run api`                     | Refresh the API client: `api:fetch` saves the gateway's spec to `openapi/gateway.json` (`GATEWAY_URL`, default `http://localhost:8080`), `api:generate` regenerates `src/app/api` |

## API client

`src/app/api` is generated by [ng-openapi-gen](https://github.com/cyclosproject/ng-openapi-gen); don't edit
it. Call an operation through `Api`, which returns a Promise:

```ts
const teams = await inject(Api).invoke(listTeams, {}); // listTeams from api/functions
```

Without a running gateway, use the spec its tests save:
`GATEWAY_SPEC=../Fairness-Checker/target/openapi.json npm run api` (after `sh mvnw test` there).

The spec marks every response field the gateway always sends as required, and the ones that may be null as
`T | null`, so the types say exactly what arrives. After changing the gateway's API, run `npm run api` and
commit `openapi/gateway.json` with the regenerated client.

## Sessions

- `AuthService` (`core/auth/auth.ts`) keeps the user and the 15-minute access token in memory, as signals.
  The refresh token is an httpOnly cookie for `/api/v1/auth` that the page never sees.
- On start, the app asks for a new access token with that cookie, so a reload stays signed in.
- `authInterceptor` sends the token with every `/api` request. It renews a token about to expire first
  (concurrent requests share one refresh, and tabs take turns through the Web Locks API), and retries a
  request the gateway answers with 401 `UNAUTHENTICATED` once. If the session can't be renewed, the user goes
  to the sign-in page and comes back afterwards.
- Signing out in one tab signs out the others (BroadcastChannel).
- `authGuard`, `guestGuard` and `roleGuard(...)` shape navigation only; the gateway checks every permission.

## Errors and loading

- Forms put the gateway's field errors under their fields (`shared/forms/server-errors.ts`) and mark their
  requests `handlesErrors()`.
- Any other failed request shows a snackbar (`core/http/error-interceptor.ts`), with the request id for
  server errors.
- `PASSWORD_CHANGE_REQUIRED` sends the user to change their password.
- The shell shows a progress bar while requests or lazy routes load.

## Layout

```
src/app/
  api/        generated client (npm run api)
  core/       auth (service, interceptor, guards), http (errors, loading), layout (shell, navigation)
  features/   pages, one folder each (auth: sign-in, change password)
  shared/     reusable pieces (form error helpers)
```

Pages not built yet show a placeholder; Groups 9 and 10 replace them.
