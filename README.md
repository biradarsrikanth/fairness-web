# fairness-web

The web app for the on-call fairness tracker: Angular 22 (standalone, zoneless, signals, Signal Forms) with
Angular Material. It talks only to the gateway (`Fairness-Checker`), on the same origin: the dev server
proxies `/api` to it, and in production Nginx does.

## Run it

Needs Node 22.22+ or 24.15+ and a gateway on `http://localhost:8080` (see `Fairness-Checker/README.md`).

```bash
npm install
npm start            # http://localhost:4200, /api proxied to :8080 (proxy.conf.json)
```

| Script                            | What it does                                                                                                                                                                      |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `npm start`                       | Dev server with the proxy                                                                                                                                                         |
| `npm test`                        | Unit tests (Vitest, jsdom)                                                                                                                                                        |
| `npm run lint`                    | ESLint (angular-eslint), templates included                                                                                                                                       |
| `npm run format` / `format:check` | Prettier                                                                                                                                                                          |
| `npm run build`                   | Production build into `dist/`                                                                                                                                                     |
| `npm run api`                     | Refresh the API client: `api:fetch` saves the gateway's spec to `openapi/gateway.json` (`GATEWAY_URL`, default `http://localhost:8080`), `api:generate` regenerates `src/app/api` |

## API client

`src/app/api` is generated by [ng-openapi-gen](https://github.com/cyclosproject/ng-openapi-gen); don't edit
it. Call an operation through `Api`, which returns a Promise:

```ts
const teams = await inject(Api).invoke(listTeams, {}); // listTeams from api/functions
```

Without a running gateway, use the spec its tests save:
`GATEWAY_SPEC=../Fairness-Checker/target/openapi.json npm run api` (after `sh mvnw test` there).

The spec marks every response field the gateway always sends as required, and the ones that may be null as
`T | null`, so the types say exactly what arrives. After changing the gateway's API, run `npm run api` and
commit `openapi/gateway.json` with the regenerated client.

## Sessions

- `AuthService` (`core/auth/auth.ts`) keeps the user and the 15-minute access token in memory, as signals.
  The refresh token is an httpOnly cookie for `/api/v1/auth` that the page never sees.
- On start, the app asks for a new access token with that cookie, so a reload stays signed in.
- `authInterceptor` sends the token with every `/api` request. It renews a token about to expire first
  (concurrent requests share one refresh, and tabs take turns through the Web Locks API), and retries a
  request the gateway answers with 401 `UNAUTHENTICATED` once. If the session can't be renewed, the user goes
  to the sign-in page and comes back afterwards.
- Signing out in one tab signs out the others (BroadcastChannel).
- `authGuard`, `guestGuard` and `roleGuard(...)` shape navigation only; the gateway checks every permission.

## Errors and loading

- Forms put the gateway's field errors under their fields (`shared/forms/server-errors.ts`) and mark their
  requests `handlesErrors()`.
- Any other failed request shows a snackbar (`core/http/error-interceptor.ts`), with the request id for
  server errors.
- `PASSWORD_CHANGE_REQUIRED` sends the user to change their password.
- The shell shows a progress bar while requests or lazy routes load.

## Layout

```
src/app/
  api/        generated client (npm run api)
  core/       auth (service, interceptor, guards), http (errors, loading), layout (shell, navigation)
  features/   pages, one folder each (auth, analytics, alerts, engineers, teams, oncall, admin/{users,sync,audit})
  shared/     reusable pieces (formatting, form helpers, list state, dialogs, the risk badge, date range field)
```

## Pages

| Path                                     | Who              | What                                                                                 |
| ---------------------------------------- | ---------------- | ------------------------------------------------------------------------------------ |
| `/analytics`, `/analytics/engineers/:id` | everyone         | KPIs, charts, burnout; one engineer's breakdown                                      |
| `/alerts`, `/alerts/:id`                 | everyone         | Alerts by team, severity, status and date; an alert's paging history (admins delete) |
| `/oncall`                                | everyone         | Who is on call now; shifts in a date range                                           |
| `/engineers`                             | managers, admins | Add, edit, mark inactive, remove                                                     |
| `/teams`                                 | managers, admins | Managers edit their teams; admins add and delete                                     |
| `/admin/users`                           | admins           | Logins, roles, manager teams, one-time passwords, unlock                             |
| `/admin/sync`                            | admins           | Sync status, sync now, sync runs, webhooks (replay failed ones)                      |
| `/admin/audit`                           | admins           | Who did what                                                                         |

List pages keep their filters, page and sort in the URL (`shared/list/list-state.ts`), so the back button
and shared links show the same list. Forms open in dialogs and put the gateway's field errors under the
fields; deletes ask first and show the gateway's reason when it refuses one. What a role sees only shapes the
pages: the gateway checks every request.

## Analytics

- `/analytics` loads one `GET /api/v1/analytics/snapshot` for the filter in the URL (`team`, `start`, `end`,
  `granularity`; absent means the gateway's default: every team you may see, the last 30 days). Bookmarks and
  the back button work, and links that don't parse fall back to the defaults.
- `/analytics/engineers/:id` shows one engineer's burnout score and its parts, time of day and latest alerts for
  the same dates (`GET /api/v1/scores/engineers/{id}`, then `/api/v1/alerts`).
- Pages load with `apiResource()` (`core/http/api-resource.ts`): a request per filter, the previous one
  cancelled, errors shown on the page. While the next filter loads, the last figures stay on screen, dimmed.
- Charts are ECharts through ngx-echarts, loaded only with the analytics pages. Their options are pure functions
  (`charts/chart-options.ts`), tested without drawing, and every chart has a table view. Colors live in
  `charts/palette.ts` and were checked for color-vision deficiency; severity is one blue from dark (P1) to
  light (P5).
- Fairness and burnout come from the scorer. When it's down, or a manager looks at several teams at once, the
  page says why and shows everything else.
- Date fields read and show dates day first (13/10/2026).
- **Export** (analytics and engineer pages) downloads a PDF or Excel report of exactly the days on screen, built
  by the gateway (`features/reports`). A failed download's error arrives as a Blob; `readableError()` turns it
  back into problem details. Reports cover at most 366 days.
